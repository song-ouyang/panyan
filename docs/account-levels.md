# 账户等级与成长徽章

账户等级使用 `wanpan-growth-v1`：累计有效完攀日和累计不同线路数同时达标后升级，不要求连续攀爬，不使用月榜积分，不代表 V 级能力。Lv.0 为新岩友，不授予徽章；Lv.1–10 各有一枚徽章。完整门槛见 [等级配置](../design/wanpan-levels/v1/levels.json)。

## 数据与行为

- 服务端保存独立完攀事实；重复完攀仍更新原动态，但不覆盖已经计入成长的历史日期。同日多条线路只增加一天，同一线路跨日增加天数但不增加不同线路数。
- 客户端一次明确提交使用稳定的 `clientRequestId`，失败重试复用。相同键且不同请求内容返回冲突；旧客户端不传键时，仅新线路首次记录增长。
- 历史成长依据仍保留的有效完攀记录补算，不按注册时间猜测天数；已经丢失的重复完攀日期无法恢复。
- 删除完攀记录会撤销关联成长事实、重算当前等级与有效徽章。正常休息和自然换线不扣成长。重新达标恢复原徽章，不再为同一枚徽章自动庆祝。
- 跨级时补齐所有徽章，自动庆祝仅显示当前最高等级并说明新增数量。服务端原子消费展示事件，避免两台设备重复自动播放。手动重播不增加奖励。
- 私密有效完攀参与本人等级计算；等级接口需要登录，不暴露完攀明细。

## 界面与声音

“我的”将当前账户等级收进资料头：真实头像外用对应等级的细圈装饰，昵称旁显示紧凑的 `Lv.x` 标识，不另设徽章栏目。Lv.0 保持普通头像。点击头像圈或等级后进入详情，再显示完整徽章、累计完攀日、不同线路数和距离下一级的剩余量；最高等级显示已满级。收藏区区分已获得、未解锁和因记录撤销而失效的徽章。

个人页只刷新等级，不自动弹历史补授庆祝；进入等级详情后再消费历史展示事件。新完攀或带视频投稿达标后的即时领取动效保持原行为。

本次使用用户确认的十枚黑猫徽章原图。图集按稳定的 `account-level-01` 至 `account-level-10` 标识在运行时按轮廓裁切，Lv.10 保留突出的猫耳，中文字和实时进度由客户端原生绘制。庆祝与收藏使用相同图集，同一枚徽章不会在不同页面换样式。

最终音效为 **C「木质小阶梯」**，来源 UI SFX `organic/level-up`，CC0-1.0。源文件不剪辑、不变速；音效约 1.2 秒，徽章弹入动效 1.1 秒，尾音自然结束。音量为 `0.45 × 0.913 = 0.41085`。设置中的“徽章音效”默认关闭，开启后使用这一声音；遵守系统静音。减少动态时直接显示徽章，不旋转、不飞散粒子，声音仍遵守开关。

Flutter 为主要客户端。保留的小程序提供相同等级、收藏与庆祝权益；小程序现有无视频线路投稿本身不增加成长。带视频投稿的成长由服务端支持，并在已有该功能的 Flutter 发布入口接入。

## 上线顺序

先发布含新增 schema 和成长 API 的服务端，再发布客户端。数据库升级使用项目原有幂等 migration；历史回填按账号成长锁进行，不把上线当天当作历史完攀日期。旧客户端仍可保存完攀；新增客户端需要成长 API 才能展示实时等级。

服务端和客户端分别发布。服务端沿用项目备份、migration 与 `/health`、`/ready` 检查流程；App 和微信小程序的商店/平台发布另行记录。
