# 完攀日记动效设计规范

> 版本：1.0
>
> 适用范围：微信小程序端
>
> 视觉基调：白色画布、珊瑚主行动、金色进度与奖励、黑猫静态角色资产

## 1. 设计目标

本规范吸收 Duolingo 在“即时反馈、清晰进度、阶段奖励、角色化状态表达”上的方法，以及 Emil Kowalski 与 Apple 对克制、连续、可打断动效的要求，但不复制其品牌绿色、吉祥物、版式或具体动画。完攀日记应形成自己的体验：清爽、可靠、轻快，有小动物的亲和感，但仍然像一个认真记录攀岩成长的工具。

动效的优先级如下：

1. **先快，再动。** Tab 切换和返回必须先显示已有内容，不用过场遮盖真实等待。
2. **动作必须有语义。** 动效只回答“我按到了吗”“状态变了吗”“结果成功了吗”“内容从哪里来”。
3. **保持空间连续。** 指示器、进度、Sheet 从原位置自然变化，避免无来源的飞入和缩放。
4. **高频轻、低频强。** 点赞、切换等高频动作短而轻；首次完攀新难度、联赛升级等低频里程碑才使用完整庆祝。
5. **猫用姿态表达状态，不用循环制造存在感。** 小猫可以有欢迎、思考、成功、空状态等静态版本，但不做呼吸、漂浮、抖动、眨眼等常驻 idle 动画。
6. **用户始终掌控节奏。** 动效不能锁住输入，Sheet 和庆祝弹窗出现后应立即可关闭，网络请求失败也不能把界面卡在中间态。

## 2. 视觉与语义颜色

颜色沿用项目已有 token；动效不得另建一套高饱和主题，也不得以 Duolingo 绿作为主色。

| Token | 值 | 语义 | 动效中的用途 |
|---|---:|---|---|
| `--color-bg` | `#FFFFFF` | 页面画布 | 页面与 Tab 的稳定底色，不参与闪烁或渐变 |
| `--color-surface` | `#FFFFFF` | 卡片与浮层 | Sheet、卡片、弹窗 |
| `--color-surface-soft` | `#F5F6F7` | 次级区域 | 未选中状态、输入区、骨架屏 |
| `--color-text` | `#17191C` | 主信息 | 标题、数值、关键结果 |
| `--color-text-secondary` | `#5F666D` | 次级信息 | 说明、地点、时间 |
| `--color-accent` | `#F2674F` | 主行动珊瑚色 | 主按钮、选中态、即时确认 |
| `--color-accent-strong` | `#DC513B` | 珊瑚按压底边 | 主按钮的物理层级与关键强调 |
| `--color-accent-soft` | `#FFF1ED` | 柔和珊瑚底 | 选中背景、轻提示 |
| `--color-gold` | `#E9B440` | 奖励与成长 | 进度、积分、前三名、里程碑 |
| `--color-gold-soft` | `#FFF7DD` | 奖励柔光 | 成功弹窗局部底色，不铺满页面 |
| `--color-success` | `#3F8C67` | 操作成功 | 上传、保存、加入成功的状态提示 |
| `--color-danger` | `#C94C3F` | 风险与错误 | 删除、退出、失败；不得用于普通强调 |

珊瑚表示“现在可以做什么”，金色表示“已经获得了什么”。同一组件中不要让两者争夺主按钮地位。

## 3. 动效 tokens

### 3.1 时长

| Token | 时长 | 适用场景 |
|---|---:|---|
| `--motion-instant` | `0ms` | 底部 Tab 内容切换、缓存命中、开关状态提交 |
| `--motion-press` | `130ms` | 按压缩放、图标按下 |
| `--motion-micro` | `160ms` | 点赞、勾选、状态标签、遮罩 |
| `--motion-switch` | `180ms` | 分段选择器指示器、筛选切换 |
| `--motion-sheet` | `220ms` | Sheet、Popover、居中对话框 |
| `--motion-progress` | `280ms` | 进度条、积分变化、统计数值更新 |
| `--motion-celebrate-stage` | `180–260ms` | 庆祝中的单个阶段；每个元素不连续运动超过 `300ms` |

默认 UI 动效不超过 `300ms`。里程碑庆祝可以由多个短阶段组成，但首屏内容和关闭按钮必须在 `220ms` 内可用。

### 3.2 缓动

| Token | 曲线 | 用途 |
|---|---|---|
| `--ease-out` | `cubic-bezier(.23, 1, .32, 1)` | 按压回弹、Popover、状态出现 |
| `--ease-in-out` | `cubic-bezier(.77, 0, .175, 1)` | 已在屏幕上的指示器与进度移动 |
| `--ease-sheet` | `cubic-bezier(.32, .72, 0, 1)` | Bottom Sheet 与抽屉进入 |
| `linear` | `linear` | 仅用于确定进度的时间映射，不用于页面组件入场 |

WXSS 不模拟复杂弹簧。需要手势跟手时，优先使用平台原生交互；状态切换使用上述确定曲线，避免“弹很多次”的玩具感。

### 3.3 可动画属性

默认只动画 `transform` 和 `opacity`。进度条使用 `scaleX()` 且 `transform-origin: left center`，不要动画 `width`。不动画 `height`、`top`、`left`、大面积阴影或模糊。

禁止使用 `transition: all`。每个组件必须明确列出属性、时长和缓动。

## 4. 组件动效规范

### 4.1 Press：即时按压反馈

- `touchstart` 后立即反馈，不等待接口返回。
- 普通可点击项：`scale(.97)` + `opacity(.82)`，`130ms --ease-out`。
- 大号主 CTA 可使用 Duolingo 式轻微“物理底边”：静止时底边最多 `4rpx`；按下时内容层向下 `2–3rpx`，不要动画阴影本身。
- 列表整卡可点击时只缩放卡片，不让卡片里的头像、文字、箭头分别运动。
- 网络提交后用 loading/disabled 表达处理中；按下反馈不能被延迟到请求结束。
- 关闭、删除等危险操作不使用可爱弹跳，保持直接、克制。

### 4.2 Switch：Tab、筛选与周期切换

- **底部原生 Tab：零过场。** 立即显示缓存页面，不做整页左右滑动、淡出或白色遮罩。
- 底部 Tab 只改变图标与文字选中色；不让图标持续弹跳。
- 页面内的分段选择器可移动下划线或选中底块，时长 `180ms --ease-in-out`。
- 已有缓存时，内容同一帧切换；确有助于理解时，可加一次 `100–140ms` 的轻微透明度变化，但不能先把旧内容清空。
- 切换后后台静默刷新；过期内容仍可阅读，刷新失败不应把页面替换成全屏错误。

### 4.3 Progress：进度、积分与成长统计

- 首次冷启动时直接显示真实值，不从 0 慢慢播放，避免制造假等待。
- 从旧值更新到新值时，以旧值为起点，用 `scaleX` 在 `280ms --ease-in-out` 内连续变化。
- 数值只在有明确加分时滚动一次，最长 `260ms`；频繁数据刷新不滚动。
- 进度达到 100% 时可让金色端点或勾选图标做一次 `scale(.92 → 1)`，不让整张卡片跳动。
- 上传进度必须由真实分片上传百分比驱动，不使用假进度；网络停滞时保持当前值并显示文案。

### 4.4 Sheet / Dialog：来源明确的浮层

**Bottom Sheet**

- 遮罩：`opacity 0 → 1`，`180ms --ease-out`。
- Sheet：`translateY(24rpx) → 0`，`220ms --ease-sheet`；不要从屏幕外长距离飞入。
- 打开后立即可滚动和关闭，不等待动画结束才开放交互。
- 退出使用 `160–180ms`，比进入略快。

**居中 Dialog**

- `opacity 0 → 1` + `scale(.96 → 1)`，`220ms --ease-out`。
- 从 `scale(.96)` 起，不从 `scale(0)` 起。
- 错误弹窗、删除确认不使用彩纸或角色动画。

### 4.5 Success：成功与里程碑

成功分两级，避免每次操作都像中了大奖。

| 级别 | 触发 | 表现 |
|---|---|---|
| 普通成功 | 点赞、关注、保存资料、加入约爬 | 乐观状态更新；必要时轻触觉或短 Toast，不弹庆祝卡 |
| 里程碑成功 | 首次完成某个 V 级、刷新个人最高、完成月目标、联赛晋级 | 一次性成功弹窗：遮罩 `160ms`、卡片 `220ms`、静态庆祝猫 `200ms` 淡入、金色/珊瑚碎片 `260ms` 单次散开 |

里程碑流程：

1. 结果先提交并确认成功。
2. 同一帧显示成功标题与关闭按钮。
3. 静态“庆祝猫”从 `opacity 0`、`scale(.96)` 过渡到正常状态，不做摇晃或循环。
4. 彩纸只播放一次，使用 6–10 个简化元素，仅动画 `transform/opacity`。
5. 声音和触觉各触发一次；用户可立即关闭或继续。

## 5. 声音与触觉

声音、触觉只强调有价值的“提交成功”，不能成为每次点击的装饰。

| 事件 | 声音 | 触觉 | 说明 |
|---|---|---|---|
| 普通按钮/Tab/筛选 | 无 | 无 | 视觉按压已足够 |
| 点赞 | 无 | 默认无 | 高频行为避免噪声；仅视觉即时反馈 |
| 加入约爬/发布动态 | 无或很短成功音 | `light` 一次 | 服务端成功后触发 |
| 视频上传完成 | `success.wav` 一次 | `medium` 一次 | 上传进度到 100% 且记录创建成功后触发 |
| 首次完成新 V 级/个人最佳 | `milestone.wav` 一次 | `medium` 一次 | 与里程碑弹窗同步 |
| 错误/取消/删除 | 无 | 无 | 用清晰文案和颜色，不用惩罚性震动 |

- 音频不得自动循环、叠播或阻塞页面。
- 在用户设置中保留“声音反馈”开关；关闭后里程碑仍通过视觉表达。
- 触觉调用失败必须静默，不影响主流程。

## 6. Reduced Motion 与可访问性

当系统启用“减少动态效果”时：

- 所有位移与缩放取消，仅保留 `120ms` 以内的透明度变化。
- 底部 Tab、筛选、周期选择立即切换。
- 进度直接更新到最终值，或仅淡入新数值。
- 里程碑不播放彩纸；静态庆祝猫、标题和结果直接显示。
- 骨架屏停止脉冲，使用固定 `opacity: .7`。
- 声音反馈遵循应用声音开关；触觉不依赖动画完成回调。

动效不能是唯一的信息载体。选中态必须同时有文字/颜色/形状变化，上传与成功状态必须有可读文案。

## 7. 性能红线

动效优化不能掩盖卡顿，以下规则是上线门槛：

1. **高频 Tab 不重复冷请求。** 页面先读内存/本地缓存，再按 TTL 静默刷新；同一接口需做 in-flight 去重。
2. **返回页面不清空已有列表。** `onShow` 刷新时保留内容，只在首次无数据时展示骨架屏。
3. **列表操作使用局部 `setData`。** 点赞、加入、评论数变化只更新目标路径，不重新写入整个大列表。
4. **视频默认展示封面。** 屏幕外视频不自动播放，避免同屏挂载多个活跃解码器。
5. **图片使用缩略图和懒加载。** 列表不在切页关键路径解码原始大图。
6. **不使用高成本视觉效果。** 重复列表中禁止 `filter`、`backdrop-filter`、`mix-blend-mode`、大面积动态阴影与模糊。
7. **不动画布局属性。** 禁止用 `width/height/top/left/margin` 驱动连续动画；进度用 `scaleX`，移动用 `translate`。
8. **不使用 `transition: all`。** 只声明实际变化的 `transform`、`opacity`。
9. **循环动画有硬限制。** 除首次空数据的 3–6 个骨架占位外，不允许无限循环；页面不可见时必须停止。
10. **动画不锁输入。** 不以 `setTimeout` 作为可点击条件；关闭和返回应随时响应。

建议验收指标：缓存命中的 Tab 在用户感知上同帧出现；按压反馈在一帧内开始；普通动效保持 60fps；低端机快速连续切换不出现白屏和重复请求堆积。

## 8. 页面映射

| 页面/流程 | 使用的动效 | 明确不做 |
|---|---|---|
| 启动页 | 首次进入时文案/按钮 `180–220ms` 淡入；猫与攀岩主画面保持静态 | 不让猫呼吸、漂浮或反复眨眼；不强制等待品牌动画结束 |
| 岩馆 Tab | 缓存列表即时显示；门店卡按压 `130ms`；城市筛选指示 `180ms` | 不做整页滑入；不在每次 `onShow` 清空列表重载 |
| 广场 Tab | 缓存动态即时显示；点赞 `130–220ms` 单次反馈；发布成功局部插入 | 不让全部动态逐条入场；不自动播放多个视频 |
| 排行 Tab | 全国/省/市指示器 `180ms`；积分变化 `280ms`；前三名仅首次结果出现时一次淡入 | 不做领奖台永久跳动、火焰循环或切榜白屏 |
| 我的 Tab | 日历/周期即时切换；难度进度从旧值更新；个人最佳触发里程碑弹窗 | 不让统计每次进页面都从 0 重播；不让成长猫循环 idle |
| 约爬 | 创建 Sheet `220ms`；人数步进器按压；加入/发布成功轻触觉 | 不让表单从远处飞入；不因动画延迟提交或关闭 |
| 路线详情 | 完攀视频点赞乐观更新；评论与完攀数局部刷新 | 不重新渲染整条排行榜；不为每个卡片添加入场动画 |
| 视频打卡 | 真实上传进度 `scaleX`；上传完成普通成功；首次 V 级升级用里程碑 | 不用假进度，不在分片停滞时循环闪烁 |
| 通用弹窗 | 居中弹窗 `scale(.96 → 1)` + opacity；错误弹窗只用清晰反馈 | 不从 `scale(0)` 弹出；不在危险确认里播放可爱庆祝 |

## 9. Before / After / Why

| Before | After | Why |
|---|---|---|
| 每次切回 Tab 都先清空并重新请求 | 缓存内容同帧显示，过期后后台静默刷新 | 用户感知速度比装饰性转场更重要，也避免白屏 |
| 为了“更萌”让小猫持续漂浮或摇摆 | 用欢迎、思考、空状态、成功等静态姿态表达情绪 | 角色仍有性格，但不抢内容注意力、不消耗性能 |
| 所有卡片依次飞入 | 列表稳定出现，只给当前按压项即时反馈 | 高频浏览不需要重复表演，滚动更稳 |
| 底部 Tab 使用整页左右滑动 | 原生 Tab 即时切换，仅更新选中图标和文字 | 高频导航动效会让应用显得更慢，也容易打断连续操作 |
| 进度条每次进入都从 0 播放 | 首次直接显示真实值，仅在旧值变化时连续过渡 | 避免假等待，并让动画真正表示成长变化 |
| 点赞成功后等待接口再变色 | 先乐观更新并播放一次轻反馈，失败再回滚 | 立即确认用户意图，降低操作迟滞感 |
| 所有成功都弹庆祝卡并播放声音 | 普通成功用局部反馈；仅首次 V 级、个人最佳等触发庆祝 | 稀缺的庆祝更有价值，减少声音与弹窗疲劳 |
| Sheet 从屏幕外长距离飞入且动画完成前不可点 | 从邻近位置 `24rpx` 进入，`220ms` 内完成，并始终可关闭 | 空间关系更可信，且符合可打断交互原则 |
| 通过大阴影、模糊、混合模式营造活泼感 | 使用白底、珊瑚动作、金色奖励和轻量 transform/opacity | 保持品牌辨识度，同时降低列表滚动和切页绘制成本 |

## 10. 被拒绝的动画候选

| 候选 | 结论 | 拒绝原因 |
|---|---|---|
| 小猫常驻呼吸、漂浮、摇尾巴 | 拒绝 | 没有状态含义，长期分散注意力；用户已明确不希望猫随意动 |
| 底部 Tab 整页滑动或淡出 | 拒绝 | 高频操作被人为变慢，连续切换容易掉帧 |
| 岩馆/动态/排行所有卡片逐条入场 | 拒绝 | 大量节点同时动画，首屏慢且滚动不稳 |
| 领奖台、火焰、积分常驻跳动 | 拒绝 | 奖励失去稀缺性，并形成持续视觉噪声 |
| 点赞、Tab、筛选每次都播放声音或震动 | 拒绝 | 高频反馈容易打扰，且不符合“只强调有价值提交”的原则 |
| 大面积视差、模糊玻璃与动态阴影 | 拒绝 | 与白色轻量主题不一致，低端机绘制代价高 |
| 用加载动画遮住缓存内容 | 拒绝 | 动画掩盖了可以避免的等待，破坏真实速度感 |
| 失败、删除确认使用弹跳和彩纸 | 拒绝 | 情绪语义错误，会弱化风险提示 |

## 11. 落地顺序

1. **P0 性能基础：** Tab 缓存优先、请求去重、保留旧内容、图片/视频懒加载、局部 `setData`。
2. **P1 通用反馈：** 统一 Press tokens、分段指示器、Sheet/Dialog、Reduced Motion。
3. **P1 关键连续性：** 上传进度、积分变化、成长统计从旧值到新值。
4. **P2 里程碑：** 首次 V 级、个人最佳、月目标、联赛晋级的一次性成功编排。
5. **P2 体验验收：** 连续切换四个 Tab、弱网刷新、长列表滚动、低端机、减少动态效果模式。

任何新增动效在进入开发前都必须回答三个问题：它解释了什么变化？它是否让高频流程变慢？关闭动画后信息是否仍然完整？任一问题没有清晰答案，就不应实现。

## 12. 参考依据

- [How Duolingo's streak builds a habit](https://blog.duolingo.com/how-duolingo-streak-builds-habit/)：反馈系统服务于持续行为，而不是用动画遮盖等待。

## 13. 核心旅程编排

完整动效不是“每个元素都动”，而是让相邻状态之间保持明确因果。视频完攀采用以下单向旅程，任何阶段失败都停留在当前可恢复状态：

`选择线路 → 选择视频 → 上传视频 → 保存记录 → 等待审核 / 完攀确认 → 返回线路`

| 阶段 | 用户看到的变化 | 动效参数 | 恢复方式 |
|---|---|---|---|
| 选择视频 | 三步进度轨第 1 节点变为完成，第 2 节点成为当前步骤 | 节点 `scale(.92 → 1)`、颜色过渡 `180ms --ease-out` | 可随时更换视频 |
| 上传视频 | 显示真实 OSS 分片百分比；阶段标题从“视频已选好”切到“正在上传” | 文案先退后进，各 `80ms`；进度 `scaleX` `180ms` | 分片自动重试；失败保留本地视频 |
| 保存记录 | 上传到 `100%` 后明确切换为“正在保存”，不再伪装仍在上传 | 阶段文案 `160ms` 交叉淡化 | 已上传 URL 留在当前页面，保存失败只重试 POST，不重传视频 |
| 等待审核 | 第 3 节点完成，显示“审核通过后计分”；不播放庆祝声音和粒子 | 结果容器 `opacity + translateY(12rpx)` `220ms` | 可回线路，或从“我的动态”查看审核状态 |
| 自动通过 | 第 3 节点完成，显示真实积分；仅首次 V 等级播放一次里程碑 | 普通成功 `220ms`；里程碑碎片 `520ms` 单次 | 主行动返回当前线路 |
| 返回线路 | 显示本次结果确认卡；审核通过时真实完攀人数做一次短确认 | 卡片 `160/220ms`；数值 `.94 → 1.08 → 1` `280ms` | 继续浏览视频或再次打卡 |

发布动态采用同样的真实性原则：`选择图片 → 上传 → 提交 → 已发布 / 已提交审核`。只有明确 `approved` 才插入公开广场并触发成功反馈；`pending` 只显示审核确认，不在公开列表制造“出现后又消失”的错觉。
